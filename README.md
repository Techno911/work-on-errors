# Работа над ошибками

Полный исходный код платформы для разбора звонков и переписок отдела продаж. Менеджер сохраняет разговор и пишет самоанализ, руководитель даёт обратную связь, команда собирает правила в методичку и проверяет знания.

В репозитории находятся интерфейс, сервер, схема данных, интеграции, модельные промпты и тесты. Пример запуска использует вымышленную команду и отдельную локальную базу. Внешние сервисы подключаются своими настройками.

## Запустить локальный пример

Понадобятся Git, Docker с Compose, Bash и OpenSSL. Для разработки без контейнеров также нужен Node.js; окружение сборки описано в Dockerfile каждого приложения.

```bash
git clone https://github.com/Techno911/work-on-errors.git
cd work-on-errors
bash scripts/bootstrap-env.sh
docker compose up --build -d
```

[Открыть локальную платформу](http://localhost:15173)

Скрипт создаёт локальный `.env` со случайными паролями и секретами. Он не перезаписывает существующий файл. Не добавляйте `.env` в Git и не отправляйте его другим людям.

Демо-адреса для входа и соответствующие переменные паролей перечислены ниже. Значения паролей находятся в вашем локальном `.env`, а не в этом репозитории.

| Роль | Адрес для входа | Пароль из вашего `.env` |
|---|---|---|
| Администратор платформы | `admin@example.invalid` | `SEED_ADMIN_PASSWORD` |
| Владелец компании | `owner@example.invalid` | `SEED_DEMO_PASSWORD` |
| Руководитель продаж | `reviewer@example.invalid` | `SEED_DEMO_PASSWORD` |
| Менеджеры | `manager1@example.invalid` … `manager4@example.invalid` | `SEED_DEMO_PASSWORD` |

Готово, когда открывается страница входа, можно войти менеджером и руководителем, а сервер отвечает на проверку состояния базы:

```bash
curl http://localhost:13000/api/health
```

В ответе должно быть `db: connected`. Сборка при первом запуске занимает больше времени, чем последующие старты.

Посмотреть состояние и журналы:

```bash
docker compose ps
docker compose logs --tail=80 backend
```

Остановить пример с сохранением данных:

```bash
docker compose down
```

## Пройти один рабочий цикл

1. Войдите менеджером. Добавьте текст учебного разговора и заполните самоанализ.
2. Отправьте запись на проверку. Войдите руководителем и оставьте обратную связь.
3. Вернитесь менеджером и подтвердите чтение. Дополните разбор от лица руководителя: менеджер увидит, что требуется новая отметка.
4. Откройте форму следующей записи и вернитесь к прежним разборам. В инструкции доступны помощь и возврат подсказки первых шагов.

Начать можно с текста: для этого пути не нужны CRM, распознавание речи, языковая модель, почта или Telegram. Нормы длины самоанализа и обратной связи задаются в настройках компании; короткая заглушка может не пройти проверку.

## Что находится в коде

| Раздел | Назначение |
|---|---|
| `frontend/` | React-интерфейс менеджера, руководителя, владельца компании и администратора |
| `backend/` | NestJS API, права доступа, рабочие записи, спринты, уведомления и отчёты |
| `packages/ui/` | Исходники компонентов и дизайн-токенов, необходимые интерфейсу |
| `scripts/sql/` | Схемные изменения из истории развития платформы |
| `scripts/` | Локальные вспомогательные инструменты и проверочные сценарии |
| `docker-compose.yml` | Отдельный контур приложения и PostgreSQL |

Код адаптеров CRM, распознавания и языковых моделей сохранён. Промпты находятся рядом с рабочей логикой:

- `backend/src/llm/ollama.service.ts` содержит обращение к моделям и формирование запросов;
- `backend/src/playbook/playbook-detection.service.ts` относится к работе с кандидатами в методичку;
- `backend/src/attestation/attestation.service.ts` содержит сценарии проверки знаний.

## Подключить свои сервисы

| Возможность | Что требуется |
|---|---|
| Битрикс24 и amoCRM | Собственное подключение CRM и ключ шифрования её секретов |
| GigaAM | Отдельно запущенный сервер распознавания и его адрес `STT_BASE_URL` |
| SaluteSpeech | Собственный ключ `SALUTE_AUTH_KEY`; этот сервис может списывать деньги |
| Ollama | Собственная среда запуска моделей и параметры `OLLAMA_*` |
| SMTP и Telegram | Собственные настройки отправки; для локального текстового примера они не нужны |

Веса моделей, учётные записи внешних сервисов и доступы к чужим серверам не являются частью репозитория. GigaAM и Ollama работают отдельными сервисами; код платформы содержит их клиентские адаптеры.

Для своей команды используйте [план адаптации](docs/ADAPTATION.md). Границы локального режима и обращение с данными описаны в [правилах безопасности](SECURITY.md).

## Разработка и проверки

```bash
npm ci
npm run build
npm test --workspace backend -- --runInBand
```

Сборка включает проверки компонентов, оформления и согласованности версии. Тестовые фикстуры синтетические. Проверки интеграций с вашими внешними сервисами требуют отдельной настройки; успешная локальная сборка не означает, что эти сервисы уже подключены.
