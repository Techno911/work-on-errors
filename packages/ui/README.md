# @chirkov/shell

Общая презентационная оболочка платформ ЧиП. Пакет держит токены, локальные шрифты,
точный векторный знак, контролы и геометрию экрана входа. Авторизация и продуктовые тексты
остаются в приложении-потребителе.

## Подключение

Вариант 1 — приватная git-зависимость, закреплённая полным хешем коммита:

```json
{
  "dependencies": {
    "@chirkov/shell": "git+ssh://git@<private-host>/<team>/chip-shell.git#<full-commit-sha>"
  }
}
```

Вариант 2 — локальный tarball:

```bash
npm ci
npm pack
```

Выпуск — это `npm pack`: `prepack` сам собирает пакет и витрину и гоняет ворота (замер 360 и 390, `layout-contract`, перепись; около двух минут); при красном замере код не 0 и tarball не создаётся.

Полученный `chirkov-shell-0.9.3.tgz` кладётся, например, в `vendor/` платформы:

```json
{
  "dependencies": {
    "@chirkov/shell": "file:vendor/chirkov-shell-0.9.3.tgz"
  }
}
```

Для обычного CSS:

```ts
import '@chirkov/shell/styles.css';
```

Для Tailwind 4 импорт темы ставится после Tailwind; он уже включает базовые стили пакета:

```css
@import "tailwindcss";
@import "@chirkov/shell/theme.css";
```

## Источник токенов

`tokens/figma.json` — буквальная выгрузка библиотеки Figma; `src/tokens.css` и
`src/theme.css` генерируются из неё командой `npm run tokens:build` и вручную не правятся.
Многорежимная коллекция «06 Документ» даёт широкие значения в `:root` и
узкие в `@media (max-width: 1023.98px)`; печать всегда возвращает широкую шкалу.

Известное ограничение Figma: разрядка надзаголовка хранится как STRING `0.08em`.
Привязать переменную к `letterSpacing` нельзя, потому что свойство в Figma числовое;
поэтому узлы библиотеки держат статичные 8%.

## Docker

Tarball должен входить в build context до `npm ci`; `package.json` и lock-файл должны ссылаться
на один и тот же путь `file:vendor/...`. Для git-зависимости сборщику нужны read-only deploy key,
`known_hosts` приватного git-хоста и сеть на шаге `npm ci`; секрет передаётся BuildKit secret/SSH
mount и не копируется в слой образа. Шрифты находятся внутри tarball, поэтому контейнеру не нужен
доступ к Google Fonts или другому CDN.

## Публичный API

- оболочка: `AppShell`, `NavItem`, `SidebarToggle`, `UserBlock`, `TopBar`;
- экран входа: `LoginShell` и структурные `LoginPromise`, `LoginPromiseInset`;
- типовой экран: `Card`, `ListRow`, `Table`, `Badge`, `Avatar`, `Button`, `ButtonLink`, `IconButton`, `Input`,
  `Textarea`, `Select`, `Field`, `DateField`, `ProgressBar`, `Tabs`, `EmptyState`;
- выбор: `Checkbox`, `Radio`, `Switch`, `Chip` — с зоной нажатия не меньше 44;
- обратная связь: `Notice`, `Modal`, `Dropdown`, `Tooltip`, `FileField`;
- документ: `DocumentSurface` — обязательный корень слоя «Документ»;
- уведомления: `Toaster`, `toast` (в `AppShell` точка монтирования уже есть);
- бренд: `BrandMark`, `BrandLogo`;
- чистые функции меню: `activeNavPath`, `flattenNavItems`, `visibleNavItems`, `navBreadcrumbs`.

`Button`, `Input`, `Textarea`, `Select`, `Badge` и другие визуальные примитивы намеренно
не принимают `className` и `style`: их высота, радиус, кегль и цвет принадлежат пакету.
У `Button` высота является минимальной: при увеличенном системном тексте подпись не
срезается многоточием, а переносится по пробелам и увеличивает контрол. Слова внутри
`Button`, `Tabs.Tab`, `Badge`, `Checkbox`/`Radio` и `NavItem` не разрываются. Проп
`Button.align="center|start"` управляет подписью; по умолчанию обычная кнопка центрирована,
а `fullWidth` выровнена по началу и прижимает правую иконку к краю.
`ButtonLink` переносит тот же вид на ссылку: корень по умолчанию `a`, а через `as`
можно передать Link роутера. `IconButton` требует `aria-label`, имеет размеры md/sm,
тона neutral/danger и необязательный `count`: ноль скрывается, значения выше 99
показываются как `99+`.
`Button.loading` и `ButtonLink.loading` сохраняют подпись и ширину, заменяют левую
иконку индикатором, ставят `aria-busy` и блокируют действие. Вращение индикатора
включается только при `prefers-reduced-motion: no-preference`.
Пакет не использует `overflow-wrap: anywhere`: содержимое переносит слишком длинное
слово через `break-word`, не уменьшая обычный min-content до одной буквы, а подписи
контролов переносятся только по пробелам.
`Input.leadingIcon` добавляет левую иконку, `Input.trailingText` — связанную с полем
единицу `%`, `₽` или `дней`. `Input.align="start|end"` задаёт логическое выравнивание;
`end` предназначен для чисел и сумм и включает цифры одинаковой ширины (`tabular-nums`).
`Input.trailingAction` принимает действие справа, обычно `IconButton size="sm"` для
копирования или очистки. `Input.font` и `Textarea.font` выбирают `sans|mono`;
`Textarea.resize` выбирает `vertical|none`, по умолчанию `vertical`.
`Input type="password"` всегда рисует
встроенную кнопку «Показать/скрыть пароль» с зоной 44; отдельный
местный PasswordInput не нужен. `Checkbox.indeterminate` задаёт частичный выбор
с нативным `indeterminate` и `aria-checked="mixed"`.
`Field` оборачивает один `Input`, `Select` или `Textarea` и сам связывает подпись,
подсказку и ошибку через `id`, `htmlFor` и `aria-describedby`; `required` и ошибка
передаются контролу, поэтому местная обёртка поля платформе не нужна.
`DateField` заменяет системный `input[type="date"]` тремя `Select` для дня, месяца
словом и года. Он принимает и отдаёт только ISO `yyyy-mm-dd` или пустую строку,
учитывает длину месяца и високосный год; обязательные `minYear` и `maxYear` задают
диапазон выбора. Сохранённая дата вне диапазона остаётся видимой и доступной в списке.
Контейнеры раскладки `AppShell` и `Card` принимают `className`. У `Card` есть закрытые
слоты `title`, `description` и `action`, а также явные варианты `padding="none|sm|md|lg"`,
`surface="surface|canvas"` и `radius="card|block"`. `className` у Card предназначен только
для внешней раскладки: отступ, место и размер в сетке. Вид карточки классом не меняется —
пакетные стили намеренно объявлены вне `@layer` и сильнее утилит Tailwind.
Card по данным получает явный `tone="neutral|accent|success|warning|danger"`;
пакет сам выбирает пару фона и рамки. `elevation="flat|raised"` задаёт уровень;
по умолчанию карточка `flat`. Если `tone` не передан, сохраняется обычная
поверхность пакета. `Card` передаёт `ref` корневому элементу; `interactive` добавляет
пакетные hover/focus-состояния, а роль, `tabIndex` и обработчики задаёт платформа.
Свойства раскладки из `className` (`width`, `max-width`, внешние отступы, место в сетке)
работают, но утилиты фона, рамки, радиуса, внутренних отступов и тени не меняют вид.
`Card.as` делает весь корень ссылкой, кнопкой или Link роутера и включает пакетные
hover/focus-состояния. Неинтерактивная Card без `as` остаётся обычным контейнером.

`NavItemConfig.children` объявляет раскрывающуюся группу и её главы в том же источнике,
из которого AppShell берёт активный пункт, заголовок и крошки. Необязательный
`AppShell.title` заменяет только заголовок TopBar: активный пункт и крошки по-прежнему
вычисляются из текущего пути. `AppShell.description` добавляет под единственным `h1`
строку контекста; отдельный PageHeader платформе не нужен. `AppShell.breadcrumbs`
заменяет автоматические крошки
динамическими именами из данных страницы: `{ label, href? }`. Все пункты, кроме последнего,
ведут через тот же `onNavigate`, что и меню; последний всегда получает
`aria-current="page"`. `progress` задаёт
`completed/total`: незавершённая глава показывает счётчик, завершённая — отметку.
Активная группа раскрывается автоматически; вручную раскрыта ровно одна группа.
Пункт с `path` ведёт по маршруту, а пункт с `id` и `onSelect` выполняет действие без
подмены адреса. `count` показывает очередь; `disabled` вместе с `disabledReason`
оставляет пункт фокусируемым и объясняет причину в подсказке. В свёрнутой панели
подсказки всех пунктов выходят через portal и не обрезаются прокруткой. Строка
`AppShell.sidebarFooter` живёт между меню и блоком пользователя и скрывается только
в свёрнутом состоянии.

`Chip` — управляемая кнопка фильтра: `pressed` напрямую попадает в `aria-pressed`,
`onPressedChange` меняет выбор, `count` показывает число объектов. `icon` рисует
пакетный слот 16 px слева от подписи; SVG в `children` передавать нельзя. `tone="warning"`
подсвечивает очередь внимания, не подменяя выбранное состояние.
`ListRow` по-прежнему принимает структурные `status`, `title` и `meta`; составной режим
через `children` собирает несколько неинтерактивных частей внутри одной кнопки-строки.
Вложенные кнопки и ссылки в `ListRow` недопустимы: действием остаётся вся строка.

`Table` принимает обязательные `caption`, `rows`, `rowKey`, `columns`, `mobile` и `empty`.
Режим `mobile="cards"` на телефоне прячет шапку и ставит `mobileLabel ?? header`
над каждым значением; `mobile="scroll"` сохраняет широкую таблицу и показывает тень
только у края с реально скрытым продолжением. `numeric` выравнивает колонку вправо и
включает `tabular-nums`; `align` имеет приоритет. `action` добавляет последнюю колонку,
`rowAction` делает всю строку одним клавиатурным действием, а `stickyFirstColumn`
закрепляет первый столбец. В строке с `rowAction` нельзя размещать вложенные контролы.
Действия строки передаются как `Button size="sm" variant="secondary"` и
`ButtonLink size="sm" variant="link"`: в широкой таблице они стоят справа одним рядом
с gap 8, а ячейка имеет вертикальный отступ 4 и сохраняет строку 44. В карточке ряд
стоит слева и переносится; gap по горизонтали 8, по вертикали 12, чтобы зоны 44
соседних строк не пересекались. Видимого заголовка колонки действий нет, доступное
имя остаётся для скринридера. `empty` выводится после прокручиваемой таблицы у левого
края, переносится по словам и всегда остаётся в видимой ширине. Заголовок использует
роль overline на фоне `canvas`, строки — не ниже 44 px; печать и слой `DocumentSurface`
автоматически сохраняют широкий табличный вид. Подпись `Badge` всегда занимает одну
строку, поэтому таблица отдаёт метке её естественную ширину. Пилюля содержит только
короткий статус в одно–три слова; пояснение выводится обычным текстом рядом, а не внутри
`Badge`, чтобы длинная фраза не выходила за край телефона.

`Avatar` показывает картинку либо 1–2 инициала в размерах `sm=24` и `md=32`.
Без `color` категория детерминированно выбирается по имени. `categoryColor(value)`
принимает номер 1–8, имя переменной `--chip-color-category-N` или прежний hex РО и
возвращает пару `backgroundColor` и `textColor` из системных токенов. Незнакомый цвет считается данными и помечает Avatar
`data-ds-exception="цвет из данных"`; данные платформы при этом не переписываются.

`DocumentSurface` — единственный законный способ получить вид документа и не принимает
`className` или `style`. Компонент сам
ставит `data-chip-doc`, тёмный холст, цвет текста и базовую ступень документа. Переменные
`--chip-doc-size-*`, роли `--chip-doc-text-*` и `--chip-font-doc-display` допустимы только
внутри него; вручную ставить `data-chip-doc` или использовать документные роли снаружи нельзя.
Внутри документа `Button` и `ButtonLink` вариантов secondary, ghost и link используют
роли документа; primary сохраняет общий акцентный вид.

`LoginShell.promise` — только структурный объект со строковыми заголовком, описанием и тремя
пунктами. Единственный разрешённый произвольный узел — необязательная иллюстрация фиксированной
врезки. Форма, авторизация, данные и маршруты остаются в платформе.

`FileField` всегда скрывает настоящий `input[type=file]`: человек видит зону пакета,
кнопку «Выбрать файл» и выбранный файл, но никогда системное «Файл не выбран».
`storedFile` собирает состояние серверного файла с именем, размером и действиями
«Скачать / Заменить / Удалить»; `multiple` принимает список файлов с удалением;
`variant="avatar"` показывает круглое превью и до отправки кадрирует изображение
центральным квадратом в браузере.
`Modal` монтируется portal-ом в `body`, запирает фокус, блокирует прокрутку и возвращает
фокус после закрытия по кнопке, Escape или фону. Действия шапки передаются только через
`headerActions`; `size="sm|md|lg"` задаёт общую шкалу 400 / 560 / 768,
а на телефоне любой размер занимает доступную ширину с полями. При открытии фокус получает
первый контрол содержимого, а не крестик. Лайтбокс галереи
остаётся отдельным компонентом платформы.

Контейнеры и строки имеют `min-width: 0`; атомарные контролы сохраняют минимальную ширину
самого длинного слова. На ширине до 768 px `Input`, `Textarea` и `Select`
берут `--chip-input-font-size-touch`, поэтому платформам не нужен местный iOS-фикс 16 px.

`Dropdown` монтирует меню portal-ом, не обрезается карточкой и поддерживает стрелки,
Home, End и Escape. `Tabs` доводит активную вкладку в видимую область и показывает края
прокручиваемого ряда. `Tooltip` монтирует подсказку portal-ом, открывается по наведению и фокусу, связан с самим
фокусируемым элементом через `aria-describedby` и закрывается по Escape.
`Notice.action` размещает действие в шапке, не меняя типографику заголовка.

Каждый интерактивный узел, который рисует пакет, отмечен `data-chip-control` — перепись
отличает пакетный контрол от местной вёрстки. Все `:hover` работают только внутри
`@media (hover: hover)`: касание телефона не оставляет залипшее состояние, а активные
Chip, Tabs, NavItem и акцентный ListRow не теряют выделение при наведении.

На ширине до 768 px соседние ряды `Chip` и `Button size="sm"` размещайте с зазором
не меньше 12 px: расширенные зоны касания 44 не должны перекрываться.

Единый замок оболочки входит в tarball и принимает конфиг платформы явно:

```bash
node node_modules/@chirkov/shell/gate/оболочка-канон.mjs --конфиг scripts/оболочка-канон.json
```

## Проверки

```bash
npm run check
npm run dev
```

`npm run check` запускает проверку генерации токенов, гейт литералов и API примитивов,
проверку уникальности бинарников Inter и Oswald, Vitest, библиотечную и demo-сборки,
`webcheck.py --quick` каждой из шестнадцати страниц в Chromium и WebKit, живую перепись на
360/390/768/1280/1440,
перепись собранного CSS и два изолированных consumer build — на React 18 и React 19.
Любая ломающая находка webcheck роняет проверку. Демо работает без бэкенда и показывает оболочку,
вход, три размера Modal, таблицы и слой «Документ». Отдельный браузерный контракт доказывает,
что `max-w-md` сужает Card до 448 px, а `bg-red-500` не меняет пакетный фон.

Vitest отдельно фиксирует второй слой канона 1.3: кегль поля 15 на широкой и 16 на сенсорной
ширине, цвет подписи и подвала `rgba(255, 255, 255, 0.45)`, насыщенность надзаголовка 500,
кнопки 600 и строку названия 23px.
