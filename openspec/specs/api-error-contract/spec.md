# api-error-contract Specification

## Purpose
Контракт ошибок API: неверный ввод клиента отвечает понятным 4xx, а не «ошибкой сервера» 500.

## Requirements

### Requirement: Невалидный идентификатор → 400
Все маршруты `:id` записей и спринтов SHALL валидировать идентификатор как UUID до обращения к БД; невалидный id MUST вернуть 400 с понятным сообщением.

#### Scenario: Кривая ссылка на запись
- **WHEN** клиент запрашивает `/entries/not-a-uuid`
- **THEN** ответ 400 «Validation failed (uuid)», исключения БД не возникает

### Requirement: Переполнение тела → 413
Система SHALL отвечать 413 и читаемым сообщением, когда тело запроса превышает лимит body-парсера.

#### Scenario: Слишком большая расшифровка
- **WHEN** клиент отправляет `POST /entries` с телом больше лимита
- **THEN** ответ 413 «запрос слишком большой», а не 500
